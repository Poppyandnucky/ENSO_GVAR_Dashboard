Forecast coefficient workflow comparison: gvar_kf_forecast/regenerate path vs country_diag
Generated from local code/data on 2026-08-25. No dashboard run was performed.

Scope of this note
------------------
This note only compares the forecast/dashboard scenario path:
    GVAR_LLM_pickle import -> analysis/Dash_Output/gvar_kf_forecast.py -> analysis/regenerate_dashboard_artifacts.py -> Streamlit dashboard
against:
    analysis/diagnose/country_diag.py

It intentionally ignores structural-break visual outputs and structural-break diagnostic coefficient plots.

Bottom line
-----------
For the default ENSO+Oil forecast path, country_diag is already using the same model-generation functions and the same default EM iteration count as gvar_kf_forecast.py:
- gvar_kf_forecast.py: MAX_EM_ITER = 10
- country_diag.py: MAX_EM_ITER = gkf.MAX_EM_ITER = 10
- both call gp._run_kf_em_cached(... EXO=gp.EXO, lags=gp.lags, max_em_iter=10, exo_mode="all", update_P0=True)
- both call gkf.forecast_country_from_em(...) to convert the EM result into forecast paths and saved/diagnostic coefficient objects

So if country_diag is compared to Dash_Input/gvar_forecast_results.pkl generated by gvar_kf_forecast.py, the coefficient source should match for the same country, same climate variant, same ENSO scenario, same coefficient method, and same input panel.

Important ways the comparison can still look different
------------------------------------------------------
1. country_diag has multiple coefficient concepts:
   - coefficient trajectory/stability uses fc["theta_trace"], which is res["theta_est"] from the final post-EM forward Kalman pass.
   - forecast/decomposition uses fc["forecast_methods"][COEFF_METHOD]["theta"]. With COEFF_METHOD="last", this is the terminal filtered theta from e_step_store: pack["theta_filt"][last_t], after forecast stabilization if enabled.
   - The dashboard scenario path defaults to coeff_method="last" unless the user enables "Compare forecast vs. actual for already-observed quarters" and chooses avg4/avg8.

2. The default forecast bundle has multiple model variants:
   - scenarios: default gp.EXO = ["ENSO", "OIL_YoY"], with ENSO mean/min/max paths.
   - climate_variants: refit models for combinations such as ENSO, ENSO+Oil, ENSO+HeatDry, Oil+HeatDry, IOD, etc.
   - country_diag default uses gp.EXO = ["ENSO", "OIL_YoY"]. Its HeatDry diagnostic uses HEATDRY_EXO = ["HeatDry"], which is a separate refit and should be compared only to the matching climate_variants model, not to the default ENSO+Oil bundle.

3. The regenerate script runs gvar_kf_forecast.py from cwd=analysis:
   - forecast pickle first saved as analysis/Dash_Input/gvar_forecast_results.pkl
   - regenerate_dashboard_artifacts.py then copies it to Dash_Input/gvar_forecast_results.pkl
   - Streamlit checks Dash_Input/gvar_forecast_results.pkl first, then analysis/Dash_Input/gvar_forecast_results.pkl.

4. If the panel CSV changed after the pickle was generated, country_diag refits from the current panel while the dashboard reads the old saved forecast pickle. In that case coefficients will differ even if the code path is identical.

Forecast artifact generation path
---------------------------------
1. analysis/regenerate_dashboard_artifacts.py first runs analysis/build_yield_climate_merge.py. This rewrites analysis/gvar_panel_streamlit (8 + EGY + PER).csv with HeatDry/Oil/IOD merges.
2. If forecast generation is not skipped, it runs:
       python Dash_Output/gvar_kf_forecast.py
   with cwd=analysis.
3. gvar_kf_forecast.py imports GVAR_LLM_pickle as gp with GVAR_IMPORT_ONLY=1. That means it imports gp constants/functions without running the structural-break pickle generation block.
4. gvar_kf_forecast.py runs:
       run_forecast_all_enso_scenarios()
       run_forecast_all_climate_variants()
       save_forecast_pickle(saved)
   and writes analysis/Dash_Input/gvar_forecast_results.pkl.
5. regenerate_dashboard_artifacts.py copies that file to Dash_Input/gvar_forecast_results.pkl.
6. apps/streamlit_TRP.py loads the forecast pickle and uses saved paths from the pickle. It does not rerun EM or recompute coefficients for the scenario forecast panel.

Coefficient calculation workflow in gvar_kf_forecast.py and country_diag.py
---------------------------------------------------------------------------
1. Data source: analysis/gvar_panel_streamlit (8 + EGY + PER).csv.
2. Default variables: Y = [GDP_YoY, CPI_YoY, FX_YoY, EX_YoY], Z = [ENSO, OIL_YoY], lags = 1.
3. Data enters:
       gp._run_kf_em_cached(PATH, country, COL_COUNTRY, COL_TIME, ENDO, EXO, lags, min_T, max_em_iter=10, exo_mode="all", update_P0=True)
4. gp._prepare_country_panel_cached filters to rows where all selected Y and Z columns are finite, then standardizes Y and Z country-by-country.
5. Standardized arrays enter:
       trp.kalman_core.run_kf_em(Y=Yd, Z=Xd, lags=1, window=40, max_em_iter=10, tol=1e-4, em_damping=0.0, update_P0=True)
6. run_kf_em does VARX rolling initialization, then EM iterations:
       kf_e_step_store -> rts_smoother -> em_m_step_update
   After EM, it runs a final kalman_multilag_filter with covariance_mode="fixed" and returns res["theta_est"], res["Q"], res["R"], res["e_step_store"], etc.
7. gkf.forecast_country_from_em selects terminal forecast coefficients:
   - last: pack["theta_filt"][last_t] from res["e_step_store"], then _stabilize_theta_for_forecast if STABILIZE_FORECAST is True. Current default is False.
   - avg4/avg8: averages the last 4/8 valid rows of res["theta_est"], then applies the same optional stabilization.
   - theta_trace: all valid rows of res["theta_est"], saved for coefficient trajectory/reconstruction.
8. Recursive forecast uses _roll_kf_forecast / _roll_forecast_path. H is built from lagged predicted Y and standardized future Z. The main path gets beta/Q Monte Carlo bands. Counterfactual paths such as ENSO=0 are deterministic and set the future raw driver to 0 before standardization.

Coefficient layout
------------------
With default mY=4, mX=2, lags=1, m=6. For equation eq, theta block is:
    theta[eq*m : (eq+1)*m]
Within each block:
    [L1.GDP_YoY, L1.CPI_YoY, L1.FX_YoY, L1.EX_YoY, ENSO, OIL_YoY]
Examples:
    ENSO -> GDP is eq=0, index 4.
    ENSO -> CPI is eq=1, index 10.
    OIL_YoY -> GDP is eq=0, index 5.

HeatDry / HeatDryF column order
-------------------------------
In the current model panel:
- column 28 = HeatDry
- column 29 = HeatDryYoY
- column 30 = HeatDryF

In analysis/validation/yield_climate_total.csv:
- column 4 = HeatDry2
- column 5 = HeatDryYoY2
- column 6 = HeatDryF
The current panel's HeatDry equals source HeatDry2; panel HeatDryYoY equals source HeatDryYoY2. HeatDryF is the sixth source column.
